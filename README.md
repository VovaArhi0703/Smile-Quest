# Smile Quest

Приложение для занятий по восстановлению мимики и речевых навыков. Пациент выполняет упражнения перед камерой, ведёт фотодневник и личные задачи, получает опыт и игровые награды для питомца.

Клиент написан на Flutter. Собственный API на FastAPI хранит аккаунты и прогресс в PostgreSQL. Отдельный сервис с MediaPipe обрабатывает кадры упражнений; кадры не сохраняются в базе. Один аккаунт соответствует одному профилю. Рабочая версия больше не зависит от Supabase.

## Структура

| Каталог | Содержимое |
| --- | --- |
| `lib/` | Экраны, работа с API и логика упражнений |
| `assets/` | Изображения и SVG |
| `test/` | Тесты Flutter |
| `backend/` | API данных, SQL-схема, миграции и локальный Compose |
| `exercise_server/` | Обработка упражнений и тесты распознавания |
| `deploy/` | Конфигурация двух серверов, Caddy и примеры окружения |
| `docs/` | Проверки и текущие ограничения |

Технические имена пакетов и идентификатор Android сохранены для совместимости. Название продукта — **Smile Quest**.

Для планшетов предусмотрена отдельная адаптивная компоновка в обеих ориентациях: боковая навигация, сетки карточек и камера 3:4 с панелью управления. Телефонный интерфейс сохранён. Подробности и ограничения проверки — в [docs/tablet_layout.md](docs/tablet_layout.md).

## Запуск с чистого клона

Нужны Flutter SDK, Android SDK, JDK 17 и Android с отладкой по USB. Текущие проверки выполнялись на Flutter **3.47.9**, Dart **3.13.7**. Для локального API нужен работающий Docker с Compose; для упражнений — Python 3.11 и модель MediaPipe. Контейнеры используют Python 3.13 для API, Python 3.11 для упражнений и PostgreSQL 17.

Из корня проекта:

```powershell
flutter pub get
docker compose -f backend/compose.yaml up --build -d
curl.exe http://127.0.0.1:8100/health
```

Подготовьте окружение Python и скачайте модель по [инструкции сервиса упражнений](exercise_server/README.md). Затем в отдельном терминале:

```powershell
cd exercise_server
$env:FACE_LANDMARKER_MODEL = (Resolve-Path .\models\face_landmarker.task).Path
$env:EXERCISE_AUTH_URL = 'http://127.0.0.1:8100'
$env:ALLOW_ANONYMOUS_EXERCISES = 'false'
.\.venv\Scripts\python.exe -m uvicorn exercise_server.main:app --host 127.0.0.1 --port 8001 --ws-max-size 750000
```

В другом терминале из корня проекта:

```powershell
adb devices
adb reverse tcp:8100 tcp:8100
adb reverse tcp:8001 tcp:8001
flutter run --dart-define=DATA_API_URL=http://127.0.0.1:8100 --dart-define=EXERCISE_WS_URL=ws://127.0.0.1:8001/ws
```

Если устройств несколько, добавьте `-d <device-id>`. После переподключения кабеля повторите `adb reverse`. Есть также [режим проверки упражнений без аккаунта](docs/android_usb_test.md).

## Адреса и развёртывание

При запуске и сборке передавайте `DATA_API_URL` и `EXERCISE_WS_URL` через `--dart-define`. Для облака используйте HTTPS/WSS, например `https://api.example.ru` и `wss://exercise.example.ru/ws`.

Пароли БД, приватные ключи, окружение серверов и пользовательские данные исключены из Git. Шаблоны находятся в `deploy/*.env.example`. [Инструкция развёртывания](deploy/README.md) описывает связь сервисов.

## Проверки

```powershell
flutter analyze --no-fatal-infos
flutter test
```

Тесты Python и требования к тестовой БД описаны в [docs/testing.md](docs/testing.md). GitHub Actions запускает проверки Flutter, сервиса упражнений и синхронизации задач с отдельной PostgreSQL.

## Состояние разработки

Работают регистрация, вход, профиль и питомец, прогресс, награды, фотографии, задачи с расписанием и серия заходов. Сохранены семь версий упражнений 2.0 для бровей, глаз и улыбки. Остальные упражнения каталога требуют разработки; слабое и сильное зажмуривание ещё дорабатывается.

Почтовое восстановление пароля и доставка уведомлений не подключены. Проверки на разных устройствах и с пациентами, нагрузочные испытания и восстановление резервных копий остаются отдельными этапами. Подробнее — [docs/recovery_status.md](docs/recovery_status.md).

Android release сейчас подписывается отладочным ключом. Перед публикацией в магазине настройте собственную release-подпись; файл ключа и пароль должны оставаться вне Git. iOS-сборка в рамках этой проверки не проверялась.
